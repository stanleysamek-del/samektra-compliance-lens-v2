# UX + robustness audit — Compliance Lens v2 (2026-09-01)

Three independent code-walks (core inspection flow · periphery/teams/actions/
templates · robustness/states), synthesized and de-duplicated. Every item was
verified against the code at commit `43ba998`. File:line refs are to that
commit.

## 0. What the tool is for (the yardstick)

An inspector walks a building with a phone. Photos go in; AI findings with code
citations come out; findings become assigned corrective actions; the inspector
and manager sign; the output is a defensible PDF plus CAP / LSRA / ILSM
workbooks a surveyor, AHJ, or insurer will accept. Two users must both succeed:
the **expert inspector** (speed on a phone, trust in the AI) and the **facility
manager** with no compliance background (arrives via an assignment email, must
understand what to do and what the acronyms mean).

Everything below is judged against that: does it get a photo to a signed,
scored report faster and with fewer surprises?

## 1. What already works well (keep)

- Data model is sound: actions lifecycle with DB-enforced wont_fix note,
  snapshotted checklists, photo integrity hashes, RLS everywhere.
- `HelpTip` (inline ?) and `HelpDrawer` (header ?) already exist — the help
  system needs *coverage*, not invention.
- Template ↔ inspection-type relationship reads clearly on both screens.
- `app/actions/checklist.ts` returns `{ok,error}` — the pattern the rest of
  the mutations should adopt.

## 5. Help copy — the inline ⓘ spots (HelpTip already exists)

| Where | Text |
|---|---|
| Download PDF | The signed inspection report: every photo, the finding under it, the code citation, and the inspector + manager signatures with timestamps. The archival record you keep and email to the facility director. |
| Download CAP | Corrective Action Plan — a spreadsheet of every deficiency, the fix, who owns it, the target date, and status. The document a TJC surveyor or your AHJ asks for to see problems are being tracked and closed, not just recorded. |
| Download LSRA | Life Safety Risk Assessment — scores each deficiency by Impact and Severity into a Risk Level (ASHE convention) so you can defend fixing one finding this week and another next quarter. Pre-filled; edit in Excel and the level recalculates. |
| Download ILSM | Interim Life Safety Measures — when a deficiency can't be fixed right away, TJC LS.01.02.01 / CMS K-291 require documenting compensating measures (extra rounds, fire watch, added extinguishers) until it is. Lists the 11 standard measures, pre-checks the ones that fit. |
| Finalize | Locks the inspection — no new photos, no edits — and makes the report and workbooks downloadable. Nothing is deleted; reopen any time to unlock editing. |
| Checklist score | Score = Yes ÷ (Yes + No). N.A. ("not applicable — this building doesn't have that system") is removed from the math, so it never hurts your score. Unanswered questions aren't counted but show as gaps on the report. |
| ✦ AI flagged | A photo you uploaded matched this question, so the AI answered it. Nothing is final until you confirm — tap Confirm to agree, or Yes / No / N.A. to overrule. The report marks unconfirmed answers as AI-answered. |
| AI confidence | How sure the AI is about what it SAW, not about the code. Under ~70%, look again in person: re-shoot closer and straight-on, or tell it what's actually there. |
| Needs re-photograph (punch list) | Things the AI couldn't confirm from your angle — a gauge turned away, a label out of frame. Not violations; follow-ups. Re-shoot on your next walk and mark Resolved, or Skip with a reason. |
| Not what you expected? | Deep analyze re-runs a stronger model after asking a few questions that change which code applies. Coach is a conversation — you say what to look at. Findings you wrote or edited are always preserved. |
| Sections | Group the photos inside THIS inspection ("Stair B", "3 West") — they become the PDF headings. Different from Folders (group whole inspections on History) and Templates (the reusable question sets you pick when creating an inspection). |
| Workspace switcher | Personal workspace is yours alone. A team workspace is shared — every member sees the team's inspections, folders, findings, and Chip's rules. Switching changes what you see everywhere and where new inspections save. |
| Invite role | Admin: invite/remove people, edit rules, delete the team. Member: create + edit inspections, assign and close actions. Viewer: read and download only. |
| Chip's rules | Plain-English instructions added to every photo analysis for this team ("in our ORs, always check door bottom clearance"). Apply from the next photo on; never touch the model. "Teach Chip this" in a Coach thread saves the correction here. |
| AI match terms | Comma-separated words Chip watches for. When a finding's text contains one, this question is auto-marked No for you to confirm. Leave blank for questions only a human can judge. |
| Action status | Open: nobody started. In progress: being worked. Done: the assignee says fixed, waiting on the inspector — it does NOT close the finding. Verified: inspector confirmed; only then it drops off the CAP. |
| Awaiting verify tile | Work reported complete that nobody confirmed. Riskiest items on a survey: closed to the fixer, still open deficiencies in the record. Clear before finalizing. |

## 6. Proposed order of work

**Sprint 1 — "nothing lies, nothing loses work" (P0 + the silent-failure
class), ~1 day.** Items 2-11 above + `{ok,error}` standardization + shared
SubmitButton + confirms on all destructive actions + finalize error banner.
Mostly mechanical; each is small.

**Sprint 2 — "a new user understands the screen", ~1 day.** Help copy above
wired in as HelpTips; help drawer + /welcome rewritten for Actions/Templates/
checklists/signatures; export block always visible with subtitles;
terminology sweep to "finding"; Chip introduced on the dashboard; panel
reorder (uploader up, AI-tuning cards down); finalize pre-flight checklist.

**Sprint 3 — "phone-first", ~half day.** Multi-photo queue that stays on the
page; tap targets ≥40px; severity color unification; date helper; disabled
styles; dead-code deletion; Actions CSV.

Then Part B (phone E2E) runs against a tool that has stopped hiding its
failures — which is the point of the gate.
